# PART A — ANSWER KEY WITH EXPLANATIONS

**Q1. Answer: B** — Multi-step workflows use prompt chaining: each prompt does ONE thing well, and its output becomes the structured input for the next prompt. This produces better results than single complex prompts because each step gets full model attention, errors are containable, and quality gates can be inserted between steps.

**Q2. Answer: C** — A parallel pipeline runs multiple prompts simultaneously (typically across different dimensions or perspectives of the same problem) and then feeds all outputs into a synthesis prompt. Example: run three different persona analyses simultaneously, then synthesize into one balanced view.

**Q3. Answer: B** — Tree of Thought explores branching reasoning paths — multiple approaches are considered simultaneously, evaluated for promise, and the best path is pursued further. This is superior to Chain-of-Thought for problems where the correct approach is not obvious from the start and multiple strategies should be considered.

**Q4. Answer: B** — ReAct (Reason + Act) alternates between explicit reasoning steps ("I need to find the current price") and specified action steps ("Search: current price of X"). It is the foundation of AI agent architectures where the model can use tools (search, calculator, code execution) between reasoning steps.

**Q5. Answer: B** — RAG retrieves external documents (from a vector database, document store, or search engine) and provides them to the AI as grounded context. This solves the hallucination problem for domain-specific or current information by giving the AI verified source material to work from rather than relying on training data.

**Q6. Answer: B** — APE (Automatic Prompt Engineering) uses AI to improve its own prompts — you provide the task description and desired output characteristics, and the AI generates multiple prompt candidates, evaluates them, and recommends the best version. This is prompt optimization at scale.

**Q7. Answer: B** — Skeleton-of-Thought is designed for long-form structured documents: first generate the complete skeleton (all headings and subheadings with 1-line summaries), get approval, then fill each section independently. This prevents structural drift in long documents and enables parallel generation of sections.

**Q8. Answer: B** — Automation readiness is a task-level assessment: Is the task repeating (same type, multiple instances)? Is it text-based? Is the desired output well-defined enough to evaluate? Is there a reliable way to verify quality? Tasks scoring high on all four dimensions are strong automation candidates.

**Q9. Answer: B** — For a pipeline to function without human intervention, each step's output must be in a format the next step can reliably parse. Unstructured prose outputs cannot be systematically processed; JSON, delimited tables, or precisely structured text can be. Automation-ready prompts specify output format as precisely as a function's return type specification.

**Q10. Answer: B** — Human-in-the-loop is a deliberate design choice: identify the specific steps in an automated pipeline where human judgment, ethical review, or verification is required, and build those checkpoints explicitly into the workflow design. It is NOT having humans re-do the entire process — it's strategic placement of human oversight where it matters most.

**Q11. Answer: B** — Semantic versioning applies software version discipline to prompt management: Major version (v2.0.0) when the prompt's core structure or approach changes fundamentally; minor version (v2.1.0) when performance or coverage improves; patch (v2.1.1) for small fixes. This lets teams know whether updating a prompt is a breaking change or a safe incremental improvement.

**Q12. Answer: B** — A quality gate is an evaluation checkpoint between pipeline steps that verifies the output meets defined criteria before the next step runs. Example: after the research step, check that at least 5 verified sources are cited before allowing the synthesis step to proceed. This prevents error propagation through the pipeline.

**Q13. Answer: B** — Fairness in responsible AI requires active auditing of AI outputs for systematic bias against protected groups (race, gender, age, disability, nationality). This includes both auditing training data bias and prompt-induced bias — because even a fair model can produce biased outputs when given leading or unrepresentative prompts.

**Q14. Answer: B** — Prompt-induced bias is within the prompt engineer's direct control. Examples: asking AI to evaluate a business plan written by "Sarah Chen" vs. "John Smith" — the name can trigger demographic associations in the model. Unbalanced few-shot examples (all positive examples from one demographic) teach biased patterns. The prompt engineer is responsible for detecting and correcting these.

**Q15. Answer: C** — Employee personal data (salaries, performance records, health information), client confidential information (financial data, strategic plans, contracts), and trade secrets (proprietary processes, unreleased products) must never enter consumer AI tools whose data handling terms don't guarantee enterprise-grade privacy. Public reports (A) and your own public content (B) carry no such risk.

**Q16. Answer: B** — A complete AUP for an organization covers: what uses are approved (drafting, summarizing, research assistance), what is prohibited (processing confidential data in unapproved tools), data classification rules (what data can go into which AI tool), output verification requirements (what must be checked before use), and attribution standards (how to document AI assistance).

**Q17. Answer: B** — Context injection is the practice of systematically forwarding relevant outputs from earlier steps into later prompts — typically as a structured "context so far" block. This maintains pipeline coherence without re-running expensive earlier steps and ensures each prompt in the chain has the information it needs without requiring the user to manually copy-paste between steps.

**Q18. Answer: B** — A conditional pipeline branches based on content evaluation: if Step 1 produces output of type A, proceed to Path 1; if type B, proceed to Path 2. Example: if sentiment analysis classifies a customer as "highly upset," route to escalation prompt; if "routine inquiry," route to standard response prompt. The path is not predetermined — it is content-dependent.

**Q19. Answer: C** — Performance record is the most decision-critical metadata: a user choosing a prompt from a library needs to know whether it reliably works — what success rate it achieves, which input types it handles well, what failure modes it has. A prompt created recently (A) or by a senior team member (B) has no information value without performance data.

**Q20. Answer: B** — Python batch processing for AI requires: rate limiting (sleep() between calls to avoid hitting API rate limits), exponential backoff retry logic (for failed API calls — transient errors are common at scale), and structured output parsing (to extract the information you need from each response and store it in a structured format like a dataframe or JSON file).

**Q21. Answer: B** — Selection bias is a cognitive bias that intersects with AI use: when professionals only accept and use AI outputs that confirm what they already believed, they build a biased evidence base. The fix is to explicitly prompt for counterarguments, minority views, and failure scenarios — not just the confirming evidence.

**Q22. Answer: B** — Prompt library governance ensures the library grows with quality, not just quantity. Core governance elements: review/approval process for new entries (prevents low-quality additions), version control (enables rollback, tracks improvements), retirement criteria (removes outdated entries before they cause errors), and access controls (prevents unauthorized modification of production prompts).

**Q23. Answer: B** — Professional attribution in AI use means: when a deliverable was AI-assisted, document what the AI produced, what the human verified, what the human changed, and that the professional takes accountability for the final output. This is not about crediting the AI tool — it is about maintaining professional accountability chains and enabling audit.

**Q24. Answer: B** — Recursive pipelines are designed for iterative quality improvement: run → evaluate against criteria → if criteria not met, feed output back as input with the evaluation feedback → run again. The loop continues until quality threshold is reached. This is essentially automated self-critique at scale.

**Q25. Answer: B** — AI governance is an ongoing responsibility. Models update and change behavior. Business domains evolve. Quality can drift as edge cases accumulate. Regular revalidation (sampling outputs, testing against quality benchmarks, reviewing error logs) is required to maintain pipeline reliability. "Set and forget" automation is a high-risk approach for any business-critical process.

**B1.** Explain the difference between a "sequential pipeline" and a "parallel pipeline." Give a real business example of when each is appropriate. *(2 marks)*

**Answer:** A **sequential pipeline** passes the output of Step 1 as input to Step 2, which feeds Step 3 — each step depends on the previous. It is appropriate when steps are logically dependent: you must have your research synthesis before you can write recommendations; you must have your outline before you draft sections. A **parallel pipeline** runs multiple prompts simultaneously on the same source material, then combines all outputs in a final synthesis step. It is appropriate when you want multiple independent perspectives without one influencing another: analyze a business proposal from the CFO's perspective, the COO's perspective, and a skeptical investor's perspective simultaneously, then synthesize the three views. The parallel approach prevents anchoring bias (the first analysis influencing all others) and is faster than running three sequential persona analyses.

**B2.** What is RAG (Retrieval-Augmented Generation) and why does it solve the hallucination problem better than simply telling the AI "be accurate"? *(2 marks)*

**Answer:** RAG grounds the AI's response in externally retrieved, verifiable source material. Instead of asking the AI to recall information from training, the system retrieves the relevant documents (from a knowledge base, database, or search engine) and provides them directly in the prompt as context. The AI is then instructed to answer based only on the provided material. This solves hallucination because: "be accurate" is an instruction with no mechanism — the AI still generates from statistical patterns, and confidence in accuracy doesn't correlate with actual accuracy. RAG gives the AI verified source material to work from — it can only hallucinate by directly contradicting provided text, which is far less common. The retrieval step replaces statistical recall with verified source access. Manual RAG (pasting relevant document sections into the prompt) is available to every practitioner today without any technical infrastructure.

*Marking: 1 mark for accurate RAG definition and mechanism. 1 mark for the specific explanation of why it works better than an accuracy instruction.*

**B3.** Write a Python batch processing prompt template that would process 50 customer feedback entries and classify each as Positive / Negative / Neutral with a confidence score. *(2 marks)*

**Answer:**
```python
import openai
import time
import json

client = openai.OpenAI(api_key="YOUR_API_KEY")

def classify_feedback(feedback_text: str, retry_count: int = 3) -> dict:
    """Classify a single feedback entry with retry logic."""
    prompt = f"""Classify the following customer feedback.
    
Feedback: "{feedback_text}"

Respond in JSON format only:
{{
  "classification": "Positive" | "Negative" | "Neutral",
  "confidence": 0.0-1.0,
  "key_theme": "one phrase summarizing the main point"
}}
No explanation outside the JSON object."""

    for attempt in range(retry_count):
        try:
            response = client.chat.completions.create(
                model="gpt-4o-mini",
                messages=[{"role": "user", "content": prompt}],
                temperature=0.0,  # Deterministic for classification
                max_tokens=100
            )
            result = json.loads(response.choices[0].message.content)
            return result
        except Exception as e:
            if attempt < retry_count - 1:
                time.sleep(2 ** attempt)  # Exponential backoff
            else:
                return {"classification": "ERROR", "confidence": 0.0,
                        "key_theme": str(e)}

# Process batch with rate limiting
feedback_list = [...]  # List of 50 feedback strings
results = []

for i, feedback in enumerate(feedback_list):
    result = classify_feedback(feedback)
    results.append({"id": i+1, "feedback": feedback, **result})
    time.sleep(0.5)  # Rate limiting: 2 requests/second
    if (i + 1) % 10 == 0:
        print(f"Processed {i+1}/50 entries")

# Output to structured format
import pandas as pd
df = pd.DataFrame(results)
df.to_csv("feedback_classifications.csv", index=False)
print(df["classification"].value_counts())
```

Key design elements: temperature=0 for consistent classification, JSON output for parseable results, retry with exponential backoff, rate limiting, structured output.

**B4.** What is "prompt-induced bias" and give two concrete examples of how it can occur in professional use. *(2 marks)*

**Answer:** Prompt-induced bias is bias introduced by the prompt itself — through framing, leading language, or unrepresentative examples — that pushes an otherwise neutral model toward a biased output. It is distinct from training data bias (which is outside the prompt engineer's control) because it is directly caused by how the prompt is written. **Example 1 — Framing bias in hiring:** "Review this CV from a candidate who left two previous jobs quickly. Assess their suitability for a senior role." The framing presupposes a negative interpretation of the gaps before the AI reads the CV — producing a negatively biased assessment. A neutral prompt would present the CV without framing. **Example 2 — Unbalanced few-shot examples:** Providing five examples of "effective leadership" that all feature Western, male, formal leadership styles teaches the AI that leadership looks like this — producing evaluations that rate other leadership styles lower. The fix: ensure few-shot examples represent the full diversity of the target category.

*Marking: 1 mark for accurate definition that correctly distinguishes from training bias. 1 mark for two concrete, correctly explained examples.*

**B7.** Explain what "automation ROI" means and describe the four cost categories that must be included in any honest ROI calculation for an AI automation project. *(2 marks)*

**Answer:** Automation ROI measures whether the value created by the automated AI workflow exceeds the total cost of building and running it. An honest ROI calculation must include all four cost categories: (1) **Human time cost (current state):** The fully-loaded hourly cost of all people currently performing the task manually, multiplied by hours spent per week, annualized. This is the saving that automation enables. (2) **AI tool cost:** API costs per call (input + output tokens × price per token), multiplied by projected volume, annualized. (3) **Implementation cost (one-time):** Prompt development time, testing, integration with existing systems, team training, and documentation — all valued at the relevant hourly rates. (4) **Ongoing governance cost:** Time spent on quality monitoring, prompt maintenance, model update testing, and exception handling — an often-ignored cost that typically runs 10–20% of implementation annually. Omitting any category (especially governance) systematically overestimates ROI.

**B10.** What is a "Conditional Pipeline" and design one for processing incoming customer emails — routing to different handling paths based on email type. *(2 marks)*

**Answer:** A conditional pipeline evaluates the output of one step to determine which path to take next — rather than following a fixed sequence regardless of content. Different outputs trigger different downstream prompts or processes.

**Design:**
```
STEP 1 — CLASSIFICATION:
Input: {raw_email_text}
Prompt: "Classify this email as exactly one of:
URGENT_COMPLAINT | BILLING_QUERY | FEATURE_REQUEST | GENERAL_INQUIRY | SPAM
Output: JSON: {"type": "CATEGORY", "priority": "HIGH/MEDIUM/LOW"}"

STEP 2 — CONDITIONAL ROUTING (based on Step 1 output):
IF type == "URGENT_COMPLAINT":
  → Run: Escalation Draft Prompt (AEERF framework, empathetic, urgent tone)
  → Flag: Human review required before sending

IF type == "BILLING_QUERY":
  → Run: Billing Response Prompt (grounded in billing policy doc via RAG)
  → Route: To billing specialist queue

IF type == "FEATURE_REQUEST":
  → Run: Acknowledgment Prompt (thank + log to product backlog)
  → Action: Auto-log in product management system

IF type == "GENERAL_INQUIRY":
  → Run: FAQ Match Prompt (search knowledge base, return top 3 answers)
  → Auto-send if confidence > 0.9, else human review

IF type == "SPAM":
  → Action: Archive, no response
```

**C3.** *(6 marks)* Explain the four pillars of Responsible AI. For each pillar, describe one specific professional scenario where the pillar is violated and the prompt engineering fix that would address it.

**Answer:**

**Pillar 1 — Fairness**

*Definition:* AI outputs should not systematically disadvantage or harm individuals or groups based on protected characteristics. Both the model and the prompt must be free of bias.

*Violation Scenario:* An HR team uses AI to screen CVs. The prompt includes: "We are looking for a highly energetic, dynamic team player for a fast-paced startup environment." The AI deprioritizes CVs showing career gaps (often associated with caregiving — disproportionately affecting women) and favors cultural fit language associated with specific demographic profiles.

*Prompt Engineering Fix:*
```
Screen CVs based ONLY on these evidence-based criteria:
- Must-have skills: [list]
- Relevant experience: [describe]
Do NOT factor in: career gaps (without understanding cause), institution prestige,
name, or cultural fit language. Flag any CV where you find yourself noting something
other than the listed criteria — this requires human review.
```

---

**Pillar 2 — Transparency**

*Definition:* AI-assisted outputs should be clearly disclosed where disclosure is professionally or legally required. The decision-making process should be explainable, not a black box.

*Violation Scenario:* A financial advisor uses AI to generate investment recommendations and presents them to clients as their own analysis, with no disclosure of AI involvement and no independent verification of the AI's reasoning.

*Prompt Engineering Fix:*
- Require AI to show its reasoning: "For each recommendation, explain the specific logic and evidence behind it so I can verify it independently."
- Establish a disclosure standard: any client-facing document with AI-generated analysis includes a review notation confirming the advisor verified all claims.
- Tag all AI-generated content: internal review process requires [AI-DRAFT] → [VERIFIED] status before client use.

---

**Pillar 3 — Accountability**

*Definition:* The human professional — not the AI tool — retains full accountability for the professional output. AI is a tool, not a decision-maker. Errors, harms, and professional judgments remain the professional's responsibility.

*Violation Scenario:* A lawyer submits an AI-generated legal brief to court without reviewing the cited cases. The AI hallucinated two case citations that don't exist. When questioned, the lawyer says "the AI generated them" — attempting to shift accountability to the tool.

*Prompt Engineering Fix:*
```
Generate a legal brief outline. For every case citation:
- Flag with [VERIFY: confirm this case exists and states this holding]
- Do not include case citations you are uncertain about — use [CASE NEEDED] instead
```
Then: human verification of every citation before filing. The AI is used to speed drafting, not to replace legal research.

---

**Pillar 4 — Privacy**

*Definition:* Personal data, confidential business information, and sensitive data must be protected — including from AI tools whose data handling terms don't guarantee enterprise-grade privacy.

*Violation Scenario:* An HR manager pastes an employee's full performance history, salary, medical leave records, and disciplinary notes into a free-tier ChatGPT to "get help writing a performance improvement plan." This data may be used for model training and is potentially accessible to OpenAI.

*Prompt Engineering Fix:*
```
BEFORE using any AI tool with personal data:
1. Check: Is this tool on the approved list for personal data processing?
2. Anonymize: Replace name with "Employee A", replace specific salary with "Salary band X"
3. Remove: All medical information, religious data, disciplinary history
4. Use: Only the performance observations needed for the specific task
```
Privacy-preserving prompt: "Help me write a PIP for an employee in a [FUNCTION] role who has shown [GENERAL BEHAVIOR PATTERN, no personal details]."

import openai, pandas as pd, json, time, logging
from datetime import date

logging.basicConfig(filename='pipeline.log', level=logging.INFO)
client = openai.OpenAI(api_key="KEY")

def process_response(text: str) -> dict:
    """Classify single response with retry."""
    for attempt in range(3):
        try:
            r = client.chat.completions.create(
                model="gpt-4o-mini",
                messages=[{"role": "user",
                           "content": CLASSIFICATION_PROMPT.format(response_text=text)}],
                temperature=0.0, max_tokens=150
            )
            result = json.loads(r.choices[0].message.content)
            result["raw_text"] = text
            return result
        except Exception as e:
            if attempt == 2:
                logging.error(f"Failed to process response: {e}")
                return {"sentiment": "ERROR", "confidence": 0.0,
                        "primary_theme": "ERROR", "raw_text": text}
            time.sleep(2 ** attempt)

def run_daily_pipeline():
    # Load today's responses
    df = pd.read_csv(f"surveys_{date.today()}.csv")
    
    # Batch classify with rate limiting
    results = []
    for i, row in df.iterrows():
        result = process_response(row["response_text"])
        results.append(result)
        time.sleep(0.3)  # ~3 req/sec — within free tier limits
        if (i + 1) % 50 == 0:
            logging.info(f"Processed {i+1}/{len(df)} responses")
    
    results_df = pd.DataFrame(results)
    
    # Quality check: flag if error rate > 5%
    error_rate = (results_df["sentiment"] == "ERROR").mean()
    if error_rate > 0.05:
        logging.warning(f"High error rate: {error_rate:.1%} — manual review required")
    
    # Generate synthesis
    synthesis_input = {
        "total": len(results_df),
        "sentiment_counts": results_df["sentiment"].value_counts().to_dict(),
        "theme_counts": results_df["primary_theme"].value_counts().to_dict(),
        "urgent_count": results_df["urgency_flag"].sum(),
        "top_5_negative_quotes": results_df[results_df["sentiment"]=="Negative"]["key_quote"].head(5).tolist(),
        "top_5_positive_quotes": results_df[results_df["sentiment"]=="Positive"]["key_quote"].head(5).tolist(),
        "yesterday_sentiment": load_yesterday_summary()  # from archive
    }
    
    report_response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user",
                   "content": SYNTHESIS_PROMPT.format(**synthesis_input)}],
        temperature=0.3, max_tokens=600
    )
    
    report_text = report_response.choices[0].message.content
    
    # Save outputs
    results_df.to_csv(f"classified_{date.today()}.csv", index=False)
    with open(f"report_{date.today()}.txt", "w") as f:
        f.write(report_text)
    
    logging.info(f"Pipeline complete. Error rate: {error_rate:.1%}")
